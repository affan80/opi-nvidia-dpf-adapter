# LCM security, RBAC, and supply-chain

## RBAC

`config/rbac/role.yaml` is generated by `make manifests` from
Kubebuilder markers. `make verify-manifests` diffs that output.

LCM markers grant:

- `dpuoperatorconfigs`: get/list/watch/update (finalizer), status
  get/update/patch, finalizers update. No delete.
- `deployments`: get/list/watch.
- `dpuclusters`, `dpfoperatorconfigs`: get/list/watch (Kamaji
  preflight and shared-operator lookup).
- CRDs: get/list. No delete.
- `operators.coreos.com` Subscriptions: get/list/update/patch. CSVs:
  get/list. No create/delete. OLM is observe/claim only.

Translation still owns create/update/patch/delete on emit kinds.
There are no `*` verbs or resources. Shared CRDs and the live Helm
`dpf-operator` release are not deleted by LCM.

## Tests

Unit and race coverage in `pkg/lifecycle`: install, upgrade, noop,
rollback, timeout/unknown, ownership cleanup, concurrent Ensure,
canceled context, invalid removal policy, RBAC shape, patched
govulncheck floors (`TestPatchedGovulnDependencies`).

```bash
GOTOOLCHAIN=go1.26.10 go test ./pkg/lifecycle/ -count=1
GOTOOLCHAIN=go1.26.10 go test -race ./pkg/lifecycle/ -count=1
make verify-rbac verify-manifests
make govulncheck
```

## CI

| Workflow | What |
|---|---|
| Lint | `make lint` including `verify-manifests` |
| Tests | `go mod tidy` (fail on drift), `go mod verify`, `make test`, `go test -race ./pkg/lifecycle/` |
| Security | `make govulncheck` (fails the job on findings) |
| E2E | Kind **v0.32.0** (not `latest`) |

Workflows use `permissions: {}` at the top and `contents: read` on
jobs. Actions are pinned by commit SHA. Dependabot watches `gomod`
and `github-actions`.

## Lab

`opi-nvidia-dpf-adapter-`) so live RBAC matches `config/rbac/role.yaml`.
Confirm the applied role still has no `*` verbs or resources.
